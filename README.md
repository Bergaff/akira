# Akira — выгрузка сообщений Discord

Worker с закрытой панелью, D1, R2, Queue и cron. Выбирает сообщения одного автора за период UTC, сохраняет их текст в части и, если настроен Google Диск, копирует туда готовые файлы. Есть пробный подсчёт, пауза/продолжение, перезапуск, журнал, webhook Discord и уведомления через Telegram-бота.

**Состояние:** код и локальные тесты есть, но этот экземпляр **не развёрнут в вашем Cloudflare-аккаунте**, реальные Discord / Google / Telegram не проверены. Не считайте проект принятым по §14 ТЗ до реального smoke-теста и большой выгрузки. В режиме сервера полнота зависит от прав Discord на перечисление каналов и тредов — см. ограничения ниже.

## Безопасность и правила

Автоматизация пользовательского токена может нарушать [правила Discord](https://discord.com/terms); ответственность на владельце аккаунта. Не используйте сервис для спама, доступа к чужим каналам или автоматического обхода капчи. Если Discord блокирует запросы, проверьте доступ и свежесть cookies; не обходите защиту автоматически.

**Не присылайте токены, cookies, пароли, refresh token и URL webhook в чат.** Вносите их непосредственно как **Secret** в настройках Worker. Панель закрыта паролем, файлы доступны только с сессией. Cookies сессии подписаны HMAC, HttpOnly, Secure, SameSite=Lax; POST/DELETE защищены CSRF-токеном. Выход удаляет cookies из текущего браузера, но скопированная сессия продолжит работать до 12 часов или смены `SESSION_SECRET`.

В приложении пока нет защиты от перебора пароля: до публичного использования настройте Cloudflare WAF rate limiting или Cloudflare Access перед панелью, а также используйте длинный случайный пароль. R2 bucket должен оставаться **приватным**, без public bucket и публичного URL. Тексты и служебные данные хранятся там до удаления задания; заранее проверьте тарифы и квоты Cloudflare.

## Создать ресурсы в Cloudflare Dashboard

Для Git-развёртывания код этой ветки сначала должен быть опубликован в доступном вам репозитории; текущие локальные изменения сами по себе не означают, что они уже отправлены на GitHub. Ниже ресурсы и имена соответствуют `wrangler.toml`. Разделы Dashboard могут называться немного иначе в зависимости от интерфейса аккаунта.

1. **D1**: Workers & Pages → D1 → Create database. Имя `akira-discord-export`. Скопируйте её **Database ID** и замените `REPLACE_WITH_D1_DATABASE_ID` в `wrangler.toml` в репозитории. В SQL Console **новой пустой базы** выполните целиком файл [`deploy/dashboard-setup.sql`](deploy/dashboard-setup.sql) один раз. Он создаёт таблицы и журнал миграций; не запускайте его повторно на заполненной базе. Для дальнейших обновлений используйте новые миграции, а не этот файл.
2. **R2**: R2 object storage → Create bucket: `akira-discord-export`. Не включайте публичный доступ.
3. **Queues**: Workers & Pages → Queues → создайте `akira-export` и отдельно `akira-export-dlq` (dead-letter queue). Убедитесь, что на аккаунте доступны Queues и достаточны лимиты Workers, D1 и R2.
4. **Worker**: Workers & Pages → Create → подключите репозиторий и ветку проекта. Для сборки используйте Node.js 22.12+ и `npm ci`, команду развёртывания `npx wrangler deploy`. В `wrangler.toml` уже объявлены D1 binding `DB`, R2 binding `BUCKET`, Queue producer `QUEUE`, consumer, DLQ, статические файлы и cron `* * * * *`. После первого развёртывания проверьте эти привязки в настройках Worker. Не подменяйте указанные имена bindings. При изменении имен ресурсов исправьте соответствующий `wrangler.toml` перед развёртыванием.
5. В Worker → Settings → Variables and Secrets добавьте обязательные `PANEL_PASSWORD`, `SESSION_SECRET`, `DISCORD_TOKEN` как **Secret**. Добавьте секреты Telegram и Google Диска из таблицы ниже, если они нужны, и сохраните/разверните изменения. Точные кнопки зависят от версии Dashboard.
6. Откройте адрес Worker `*.workers.dev`, войдите, нажмите «Проверить Discord», затем сделайте **пробный проход за один день**. Если тест успешен — снимите флажок пробного прохода, создайте задание с тем же периодом и запустите выгрузку. Проверьте файл вручную и получение уведомлений. Настраивайте WAF/Access до публичной эксплуатации.

Если Git-сборка уже автоматически применила привязки из `wrangler.toml`, не создавайте вторую копию consumer или cron вручную. Если привязок нет, проверьте конфигурацию развёртывания: один producer `QUEUE` → `akira-export`, consumer того же Worker для `akira-export`, DLQ `akira-export-dlq`, таймер раз в минуту и bindings `DB` / `BUCKET`.

### Переменные и секреты Worker

| Имя | Что записать |
| --- | --- |
| `PANEL_PASSWORD` | Обязательно. Длинный уникальный пароль входа в панель. |
| `SESSION_SECRET` | Обязательно. Независимая случайная строка не менее 32 символов для подписи сессий. При смене все сессии недействительны. |
| `DISCORD_TOKEN` | Обязательно для экспорта. Токен аккаунта Discord, **без** префикса `Bot `. |
| `DISCORD_COOKIES` | При необходимости: строка cookies для запросов к Discord. Не включайте секрет в логи или Git. |
| `NOTIFY_WEBHOOK` | При необходимости: полный HTTPS URL Discord webhook. |
| `TELEGRAM_BOT_TOKEN` | Для Telegram: токен созданного через BotFather бота. |
| `TELEGRAM_CHAT_ID` | Для Telegram: числовой ID чата, например `-100...` для группы. У бота должно быть право писать в этот чат. |
| `GOOGLE_DRIVE_CLIENT_ID` | Для копирования: OAuth client ID Google Cloud. |
| `GOOGLE_DRIVE_CLIENT_SECRET` | OAuth client secret того же приложения. |
| `GOOGLE_DRIVE_REFRESH_TOKEN` | OAuth refresh token пользователя, имеющего право записи в папку. |
| `GOOGLE_DRIVE_FOLDER_ID` | ID папки на Google Диске из её URL после `/folders/`. |
| `OUTBOUND_PROXY` | Необязательно: HTTPS адрес доверенного relay (см. ниже). |
| `OUTBOUND_PROXY_SECRET` | Необязательно: общий длинный случайный секрет для доверенного relay. |

Четыре значения Google Диска задаются **вместе**; если не задано ни одного, файлы остаются только в R2. Если задана лишь часть, сборка остановится с ошибкой до исправления. После заполнения секретов нажмите «Продолжить». Записи уже завершённого задания автоматически на Диск задним числом не копируются: для них потребуется новый запуск.

### Telegram

1. В Telegram создайте бота через официального **@BotFather**, сохраните токен в `TELEGRAM_BOT_TOKEN` как Cloudflare Secret.
2. Напишите боту `/start` в личном чате, либо добавьте его в нужную группу и дайте право писать. Узнайте числовой ID именно этого чата и задайте `TELEGRAM_CHAT_ID`. Например, ID можно посмотреть в ответе `getUpdates` Telegram Bot API после сообщения боту; URL запроса содержит токен и должен оставаться приватным.
3. Запустите небольшое задание: приходят события запуска, каждые 10 частей, ошибки 401/403/429 и завершение. Ошибка доставки записывается в журнал без токенов; отдельного гарантированного повтора уведомлений нет.

### Google Диск

Нужен OAuth-доступ **вашего** Google-аккаунта. В Google Cloud Console создайте проект, включите Google Drive API, настройте OAuth consent screen и OAuth client типа Web application. Добавьте `https://developers.google.com/oauthplayground` как разрешённый redirect URI. В OAuth 2.0 Playground включите использование **собственных** OAuth credentials, выберите scope `https://www.googleapis.com/auth/drive`, войдите нужным аккаунтом и обменяйте authorization code на refresh token. Эти данные дают широкий доступ к Диску: храните их как секреты и никому не показывайте. Создайте папку в своём Google Диске и укажите её ID. Тестовые приложения Google могут выдавать refresh token с ограниченным сроком действия; при его отзыве/истечении потребуется новый.

После сборки Worker загружает части в указанную папку. Перед загрузкой каждому файлу резервируется Google file ID: при повторе после обрыва проверяется уже загруженный файл, чтобы не создавать дубликат. Удаление задания из панели удаляет объекты R2 и записи D1, но **не удаляет копии с Google Диска**.

### Опциональный исходящий relay

Если инфраструктура Discord блокирует egress Cloudflare, доступен пример ограниченного relay в `relay/`. Размещайте его только на доверенной инфраструктуре с другим исходящим IP: relay получает Discord token и cookies. У него задаётся секрет `RELAY_SECRET` не менее 32 случайных символов; в основном Worker задайте тот же `OUTBOUND_PROXY_SECRET` и HTTPS URL relay в `OUTBOUND_PROXY`. Relay принимает только ограниченные GET-маршруты Discord и не следует редиректам. Развёртывание relay на том же Cloudflare не гарантирует смену egress и **не обходит капчу**. Защищайте relay отдельно и никогда не делайте его открытым прокси.

## Использование

Укажите ID или ссылку на канал/сервер, ID автора и даты. `scan` — один канал; выбор сервера запускает последовательный обход доступных текстовых каналов. Период включителен по UTC. Файлы `discord_from-..._part-001.txt` содержат только `content`, UTF-8 без BOM; разделитель — одна или две `\n` в зависимости от чекбокса. Готовые части доступны через «Лог и файлы». Прогресс по времени и ETA приблизительные. Очередь продолжает работу без открытой вкладки. При паузе текущий запрос может завершиться, но новые данные не фиксируются после паузы; продолжение повторит страницу при необходимости.

Прогон собирает страницы от новых к старым, фиксирует страницу в приватном R2 перед обновлением D1, затем формирует файлы от старых к новым. Queue передаёт только идентификатор задания, не большие буферы. Файлы пишутся в R2 до атомарной записи метаданных D1; повтор шага не должен создавать дублей. После ошибки отдельных обращений к R2/D1 могут оставаться несвязанные временные объекты — они удаляются при удалении задания. Список и журнал обновляются раз в 4 секунды. Остановленное или завершённое задание можно удалить кнопкой «Удалить»: удаление R2 и D1 идёт в фоне; Google Drive остаётся нетронутым. Для смены Discord токена замените `DISCORD_TOKEN` в настройках Worker и нажмите «Продолжить».

## Ограничения / что ещё не проверено

- **Треды сервера:** отдельно запрашиваются активные, архивные публичные, архивные приватные и приватные с участием пользователя, с пагинацией. Discord может не дать разрешение на отдельные списки или каналы; тогда задание завершится с ошибками и предупредит в журнале, а гарантировать полноту нельзя. В файлах сервера сохраняется порядок **внутри каждого канала**, а не глобальный порядок между каналами. Эти запросы ещё не проверены с реальным Discord.
- Не реализован необязательный `search`, raw JSONL, единый `_all.txt`. Часть ограничена 3000 сообщениями и 24 МиБ; при переполнении выдаётся ошибка, не происходит незаметной потери данных.
- Сохранено поле `boundary_cursor`, но согласованная двухфазная схема использует `finalized_through` с противоположным направлением (готовы более старые сообщения); прямой импорт состояния браузерного скрипта не реализован.
- Уведомления — best effort без гарантированной повторной доставки. Google OAuth, Telegram и Discord с настоящими учётными данными здесь **не тестировались**; развёртывание, 100 000 сообщений и два реальных перезапуска также не проверены. Не выдавайте локальные моки за приёмочные испытания реального сервиса.
- Пересоздание задания с тем же источником/автором/датами и другими параметрами не допускается; исключение — переход от завершённого пробного прохода к обычной выгрузке. Для обновления формата другого существующего задания нужна доработка.

## Разработка и тесты

Node.js 22.12+:

```sh
npm ci
cp .dev.vars.example .dev.vars
npx wrangler d1 migrations apply akira-discord-export --local
npm run dev
npm run typecheck
npm test
```

Локальные значения в `.dev.vars` не коммитить. Пример содержит тестовый пароль, который нельзя использовать на реальном Worker. Запуск `wrangler deploy --dry-run` проверяет сборку, но не подключение к облачным ресурсам.

Локальные тесты включают реальную SQLite-схему, mock R2/Queue, локальный mock Discord, 1832 сообщения с 429 на каждом третьем запросе, паузу/продолжение, восстановление утраченного буфера, 401, сервер с одним недоступным каналом, обнаружение активных и архивных тредов, проверку идемпотентности Google Drive на имитированном сбое, авторизацию/CSRF и уведомления. Это не заменяет реальных тестов на Cloudflare и Discord.

## Приложение для Windows

Доступен отдельный локальный вариант: задания и файлы хранятся на компьютере, Cloudflare не нужен. Инструкция по установке, безопасности и сборке установщика — в [`desktop/README.md`](desktop/README.md). Компьютер и приложение должны работать во время выгрузки; ограничения Discord сохраняются.
